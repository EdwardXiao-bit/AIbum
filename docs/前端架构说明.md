# AIbum 前端架构说明（重建版）

> 更新：2026-10-11（阶段 5 切换收口后）。适用对象：接手这份前端的同学、以及要评审 PR 的人。
> 技术栈：**原生 HTML / CSS / ES 模块**，不引框架、不引构建工具。
> 权威入口是 **`web/index.html`**（`/` 与 `/admin` 都返回它）；`web/app.html` 是别名副本。

---

## 1 · 一句话

单页应用（hash 路由），三层分明：**外壳（app.js）→ 视图（views/）→ 装配骨架（main/api/store/router/theme）**，
加一层可复用组件（`components/`）与一层设计系统（`css/tokens.css` + `components.css`）。
**所有网络请求只从 `api.js` 出去**，视图层不许自己 `fetch`。

## 2 · 目录与职责

```
web/
  index.html            ← 权威入口（/ 与 /admin 都由它渲染）。⚠️ 改入口先改这里
  app.html              ← 别名副本（/static/app.html）；内容应与 index.html 一致（只差文件头注释）
  styleguide.html       ← 设计系统自查页（交接文档，逐档主题/逐组件六态）
  css/
    fonts.css           自托管 @font-face（Noto Sans SC 可变字体）——必须最先加载
    tokens.css          语义令牌 + 6 档主题（只有值，没有选择器逻辑之外的规则）
    base.css            reset、字阶、焦点环、reduced-motion
    components.css      15 类组件 × 6 态（按钮/输入/对话框/抽屉/菜单/日历/表格/toast/队列…）
    views.css           外壳与页头等跨视图骨架样式
    library.css         相册主界面（选择器都挂在 .library 下）
    detail.css          照片详情抽屉（.detail）
    admin.css           管理后台（.admin）
    mobile.css          窄屏**覆盖层**，必须最后加载（只覆盖桌面密度：触控目标/顶栏收纳/留白）
  js/
    theme-boot.js       ★ <head> 里的**外置同步**脚本（无 defer/async/module）→ 防 FOUC
    theme.js            六档主题的读写/持久化/跟随系统（data-theme + data-choice + localStorage）
    api.js              唯一出口：/api 前缀、X-AIbum-Request 头、错误映射、XHR 上传（要进度）
    store.js            状态 + 订阅式重渲染 + 双版本计数器（accountVersion / resultVersion）
    router.js           hash 路由（#/login #/library #/photo/:id #/admin）+ /admin 路径别名
    main.js             骨架装配（入口判定 → 主题 → 路径别名 → 路由监听 → 启动鉴权）
    app.js              应用外壳（顶栏/账号面板/视图挂载/浮层/登出）+ 启动
    components/         dom · modal · toast · spinner · menu · select-menu · date-picker · avatar · photo-card · upload-queue
    views/              auth · library · detail · upload（引擎）· admin · account
```

## 3 · 启动顺序（`main.js:boot()`，每一步都有理由，别调换）

1. **入口判定**：`location.pathname === '/admin'` → 管理员入口（行为清单 8.1）
2. **应用主题**（`theme.initTheme()`；`<head>` 里的 `theme-boot.js` 已经先写过一次，防闪）
3. **`/admin` 路径别名**：pathname 是 `/admin` 且 hash 为空 → `location.replace('#/admin')`（D6 / Q1）
4. **起路由监听**（`hashchange` + `popstate`）
5. **启动鉴权**：`GET /api/auth/me` → 成功进工作区 / 失败回登录态（0.8）
6. **hash 为空**时按登录态落默认路由

> ⚠️ 第 4 步发生在第 5 步之前，所以**未登录深链 `#/photo/:id` 会被误改写成 `#/library`**——
> `applyRoute` 里那段 `deferredRoute` 暂存就是为它存在的（`main.js:56-68`）。改这里要小心。

## 4 · 数据流

```
视图事件 → store.setXxx(...) → store.emit() → 所有订阅者 render()
                                              ├─ app.js 的 render（顶栏/浮层）
                                              └─ 当前视图的 render（网格/筛选条/批量条…）
视图要数据 → api.get/post/patch/del/postForm（唯一出口）
上传      → api.upload（XHR，为了 progress；逐张串行在 views/upload.js）
```

两条**契约级**约束（改坏了会静默出错）：

| 约束 | 位置 | 为什么 |
| --- | --- | --- |
| 写请求必须带 `X-AIbum-Request: 1` | `api.js` 的 `buildHeaders` | 后端同源写校验 |
| 每个请求"发出前记 `accountVersion`、回来后比对"，不一致就作废（`error.stale`） | `api.js` 的 `request` / `upload` | 防止**上一个账户的数据闪现在新账户里**（0.4） |
| 查询结果用 `resultVersion`（`store.latest()`）判定是否过期 | `store.js` + `library.js` 的三条查询路径 | 快速连续检索/筛选时旧响应不得覆盖新结果（0.5） |

## 5 · 路由

| hash | 视图 | 说明 |
| --- | --- | --- |
| `#/login` | 认证（登录/注册/找回密码） | 未登录时任何需要登录的路由都会被挡回这里 |
| `#/library` | 相册主界面 | 默认路由 |
| `#/photo/:id` | 照片详情**抽屉**（不是并列视图） | 主界面**仍然挂着**，关掉抽屉不重建列表、不丢滚动位置（D2） |
| `#/admin` | 管理后台（并列视图） | 走 `#/admin` 或**直接访问 `/admin` 路径**都到这里 |

## 6 · 视觉与主题

- 基线：样张 B「明亮画廊」+ 六档主题（auto / light / warm / forest / dark / midnight）。
- 主题入口在**顶栏账号面板**（`.menu` 里的 `.seg`），不在这里就不是 D1 的形态了。
- 动态样式**只能走 CSSOM**（`el.style.setProperty(...)`）或切类名 —— CSP 不允许 `style="..."` 属性。
- 自托管字体：`fonts.css` 里的 Noto Sans SC **可变**字体（7.42 MB woff2）；大标题走系统宋体链。

## 7 · 环境硬约束（违反往往**静默出错**，不报错）

> 完整版在 `aibum\docs\前端-行为清单.md` 的 **§0A（E1–E5）**，这里只列后果。

1. **严格 CSP**（`app/main.py` 对所有响应下发，含 `/static/*`）：`script-src 'self'` + `style-src 'self'`，
   **没有 `unsafe-inline`**。所以禁止：内联 `<script>`、内联 `<style>`、`style="..."` 属性、`onclick=` 之类内联事件、
   `eval` / `new Function` / `javascript:` URL。
2. **防 FOUC 必须用外置同步脚本**：`<script src="/static/js/theme-boot.js"></script>`，
   在 `<head>` 里、样式表之前、**不加** `defer`/`async`/`type=module`。
3. **资源一律 `/static/...` 绝对路径**：主页挂在 `/`，相对路径会解析错（`/admin` 下更明显）。
4. **验收必须走 `http://127.0.0.1:8000`，禁用 `file://`**：`file://` 没有 CSP，会给出**假通过**
   （F2 的"六主题逐个检查"就是这么假通过的——真实服务里六张主题截图逐字节相同）。
5. 旧前端的三个文件只读：`web/style.css`、`web/app.js`，以及冻结副本 `web/legacy/`。

## 9 · 易错点（都是实测踩过的）

| 坑 | 现象 | 正确做法 |
| --- | --- | --- |
| 程序化 `.click()` 当验收 | 遮罩盖着按钮也能"点"成功 → 假通过（两次实测） | 浮层交互必须**真点**（完整 pointer/mouse 序列 + `elementFromPoint` 命中测试） |
| 合成 `KeyboardEvent` 当键盘验收 | untrusted 事件**不执行默认动作**（例如焦点在按钮上按 Enter 触发 click） | 用 CDP `Input.dispatchKeyEvent` 发**真按键** |
| `offsetParent` 判可见性 | `position:fixed` 恒为 `null` → 可见的对话框被判成"不存在" | `!el.hidden && display !== 'none' && rect.width > 0` |
| `/admin` 与 `/` 是同一个 HTML | 用 pathname 分支时忘了"hash 为空才补" | 入口判定靠 `location.pathname`；别名只在 hash 为空时补 |
| 主题入口的位置 | D1 改定后它在**账号面板**里，不在账户安全弹窗里 | 见 `#appearance-themes` |
| 详情状态不在 store 里 | `store.detail` 恒为 `null`（视图内部持有） | 需要状态就从 DOM/接口读，别假设 store 有副本 |

## 10 · 与后端的契约（不许漂移）

- **不改 `app/`**。后端是同学交付的 MVP，是本次协作的边界。
- 25 条路由、`X-AIbum-Request: 1` 写头、cookie 鉴权、`/api/search` 是 multipart 且**文字与图片互斥**
  （文字查询时 `image` 不传；图搜图时 `text` 传**空字符串**而不是省略）、`limit=100`。
- 照片状态字典：`pending` 等待分析 / `processing` 分析中 / `ready` 已分析 / `failed` 分析失败 / `deleting` 删除中。
- 单张 ≤ **20 MiB**；每人约 **500** 张；用户名 1–20 字符、密码 ≥ 8 字符；相册名 ≤ 80 字；照片名 ≤ 200 字。
